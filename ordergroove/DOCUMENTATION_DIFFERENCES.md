# OpenAPI and public documentation differences

This is the decision record for places where the authoritative OpenAPI files in
`openapi/` differ from Ordergroove's current public documentation. Simulator
behavior follows OpenAPI in each case. Public documentation was reviewed on
2026-08-01.

## Subscriptions

| Area                    | Authoritative local OpenAPI                                       | Public documentation                                                                                                 | Simulator decision                                                                                                                                                                                                                                       |
| ----------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication          | Application-scope `x-api-key` only                                | Documents both Application `x-api-key` and Storefront HMAC scopes                                                    | Implement only `x-api-key`; Storefront HMAC is outside the contract. [Authentication](https://developer.ordergroove.com/reference/authentication)                                                                                                        |
| List filters            | `customer`, `product`, `live`, `created_start`, and `created_end` | Also documents `shipping_address`, exact `created`, and exact/range `updated` filters                                | Implement only the OpenAPI filters. [List subscriptions](https://developer.ordergroove.com/reference/subscriptions-list)                                                                                                                                 |
| Update operation        | `PUT /subscriptions/{public_id}/` with a full `Subscription` body | `PATCH /subscriptions/{subscription_id}/update/` and only selected mutable fields                                    | Keep the OpenAPI method, path, and replacement body. [Update subscription](https://developer.ordergroove.com/reference/subscriptions-update)                                                                                                             |
| Cancel input and errors | No request body; response contract only declares `200`            | Optional `cancel_reason`; documents `200`, `400`, and `423`                                                          | Accept no modeled reason and retain contract-derived response handling. Cancellation still applies the documented inactive/subsequent-shipment state transition. [Cancel subscription](https://developer.ordergroove.com/reference/subscriptions-cancel) |
| Reactivate input        | No request body                                                   | Requires `every`, `every_period`, and `start_date`; optionally accepts `next_order_date`                             | Toggle the subscription to live without requiring a body. [Reactivate subscription](https://developer.ordergroove.com/reference/subscriptions-reactivate)                                                                                                |
| Frequency period        | String enum: `day`, `week`, `month`, `year`                       | The endpoint reference uses numeric period codes; another public data-model page includes numeric code `4` for years | Keep the OpenAPI string enum. [Change frequency](https://developer.ordergroove.com/reference/subscriptions-change-frequency), [data model](https://developer.ordergroove.com/docs/data-model-at-a-glance)                                                |

## Orders

| Area                   | Authoritative local OpenAPI                                                | Public documentation                                                                                     | Simulator decision                                                                                                                                                                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication         | Application-scope `x-api-key` only                                         | List and action references also permit Storefront authentication, with action-specific trust-level rules | Implement only `x-api-key`. [Authentication](https://developer.ordergroove.com/reference/authentication), [list orders](https://developer.ordergroove.com/reference/orders-list)                                                                                             |
| List filters           | `customer` and integer `status`                                            | Also documents exact/range `created` and `updated` filters and other optional expansions                 | Implement only the OpenAPI filters. [List orders](https://developer.ordergroove.com/reference/orders-list)                                                                                                                                                                   |
| Status codes           | Integer enum limited to `1`, `3`, `4`, `5`, `6`, `9`, and `10`             | Documents additional current states, including `11` through `20` with gaps                               | Validate and generate only statuses permitted by OpenAPI. [Order status codes](https://developer.ordergroove.com/reference/order-status-codes)                                                                                                                               |
| Response field names   | Uses fields such as `customer_id`, `payment_id`, and `shipping_address_id` | Uses `customer`, `payment`, and `shipping_address`                                                       | Preserve the OpenAPI names throughout the shared store and responses. [Retrieve order](https://developer.ordergroove.com/reference/orders-retrieve)                                                                                                                          |
| Action error responses | Cancel and Send Now declare only `200`                                     | Both public action references also document `400`, `403`, and `404`                                      | Keep successful response validation contract-derived; the simulator retains its explicit `404` extension for unknown IDs. [Cancel order](https://developer.ordergroove.com/reference/orders-cancel), [Send Now](https://developer.ordergroove.com/reference/orders-send-now) |

## Customers

| Area                | Authoritative local OpenAPI                                          | Public documentation                                                                              | Simulator decision                                                                                                         |
| ------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| List filters        | No query parameters                                                  | Documents `live`, `email`, and exact/range created and updated filters                            | Return the complete in-memory collection. [List customers](https://developer.ordergroove.com/reference/customers-list)     |
| Create              | `POST /customers/`, response `201`, reduced optional `Customer` body | `POST /customers/create/`, response `200`, with many required fields                              | Keep the OpenAPI path, status, and schema. [Create customer](https://developer.ordergroove.com/reference/customers-create) |
| Retrieve identifier | `/customers/{public_id}/`                                            | Describes `{merchant_user_id}`                                                                    | Index records by OpenAPI `public_id`. [Retrieve customer](https://developer.ordergroove.com/reference/customers-retrieve)  |
| Update              | `PUT /customers/{public_id}/` with a full `Customer` body            | `PATCH /customers/{merchant_user_id}/update`, limited to `extra_data`, `locale`, and `price_code` | Keep OpenAPI replacement semantics. [Update customer](https://developer.ordergroove.com/reference/update)                  |

## Items

| Area                | Authoritative local OpenAPI                                 | Public documentation                                                                                                                            | Simulator decision                                                                                                                                                                               |
| ------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| List filters        | `subscription` and `order`                                  | Also documents offer, one-time status, order status/place ranges, product, price omission, updated ranges, and incentive expansion              | Implement only OpenAPI filters. [List items](https://developer.ordergroove.com/reference/items-list)                                                                                             |
| Relationship fields | `order_id`, `subscription_id`, `product_id`, and `offer_id` | Response fields omit `_id`: `order`, `subscription`, `product`, and `offer`                                                                     | Preserve OpenAPI field names. [List items](https://developer.ordergroove.com/reference/items-list)                                                                                               |
| Create              | `POST /items/`, response `201`, accepts an `Item`           | General creation is `POST /items/create/` with placement/customer fields and response `200`; impulse upsell is a separate `/items/iu/` endpoint | Keep the single OpenAPI operation. [Create item](https://developer.ordergroove.com/reference/items-create), [create in order](https://developer.ordergroove.com/reference/items-create-in-order) |
| Delete              | `DELETE /items/{public_id}/`, response `204`                | `DELETE /items/{item_id}/delete/`, with only `403` and `404` documented                                                                         | Keep the OpenAPI path and `204`. [Delete item](https://developer.ordergroove.com/reference/items-delete)                                                                                         |

## Products

| Area       | Authoritative local OpenAPI                      | Public documentation                                                                                                                         | Simulator decision                                                                                                          |
| ---------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| List       | No filters; reduced Product schema               | Documents many search/status/group filters and optional rotating-product expansions; defaults to autoship-enabled, non-discontinued products | Return all products in the OpenAPI-shaped store. [List products](https://developer.ordergroove.com/reference/products-list) |
| Identifier | Detail path is `{id}` and state is keyed by `id` | Describes the path value as the external product ID                                                                                          | Preserve OpenAPI `id` identity. [Retrieve product](https://developer.ordergroove.com/reference/products-retrieve)           |
| Update     | `PUT /products/{id}/` with a full Product body   | `PATCH /products/{external_product_id}/` with selected mutable fields                                                                        | Keep OpenAPI replacement semantics. [Update product](https://developer.ordergroove.com/reference/products-update)           |

## Offers and entitlements

| Area                         | Authoritative local OpenAPI                                                       | Public documentation                                                                                                    | Simulator decision                                                                                                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Offer-profile filters        | No filters                                                                        | Documents `offer_profile_category` and `status`                                                                         | Return all seeded offer profiles. [List offer profiles](https://developer.ordergroove.com/reference/offer-profile-list)                                                               |
| One-time-incentive paths     | `GET` and `POST /otd/`                                                            | `GET /one_time_incentives/` and `POST /one_time_incentives/create/`                                                     | Keep `/otd/` for both operations. [List incentives](https://developer.ordergroove.com/reference/otd-list), [create incentive](https://developer.ordergroove.com/reference/otd-create) |
| One-time-incentive shape     | Reduced `OneTimeDiscount` with fields such as `customer_id`, `amount`, and `type` | Uses `customer`, item/order targeting, and a nested `incentive` object                                                  | Preserve the OpenAPI request and response shape. [Create incentive](https://developer.ordergroove.com/reference/otd-create)                                                           |
| Entitlement filter and shape | Optional `customer`; reduced `Entitlement` fields                                 | Requires `merchant`, uses optional `merchant_user_id`, and documents resource/live/grantee filters plus a rich response | Keep the OpenAPI filter and schema. [List entitlements](https://developer.ordergroove.com/reference/entitlements-list)                                                                |
