# Ordergroove REST API coverage

Reviewed: 2026-08-02

This inventory is based only on Ordergroove-owned public documentation. The complete documentation index was read from <https://developer.ordergroove.com/llms.txt>; the core model and API conventions were checked against the pages listed below. “Documented” means the endpoint page and its embedded OpenAPI fragment agree. “Implied” means two or more official pages support the behavior but no endpoint contract states it completely. “Unknown” is deliberately not treated as production behavior.

## Selected coherent workflow

The simulator supports application-scope requests that:

1. find or create a customer;
2. retrieve the seeded product;
3. list or retrieve the customer's subscription;
4. list or retrieve its upcoming order and items;
5. change subscription quantity;
6. skip that subscription on the upcoming order; and
7. observe the item moving to a deterministic subsequent order;
8. list and retrieve the customer's saved addresses and payment methods; and
9. change the shipping address or payment associated with one subscription or order.

The skip operation is documented to remove the subscription's items from the specified order and generate the next order. The public pages do not fully define generated identifiers, timestamps, pagination cursor encoding, or all recurrence edge cases. The simulator therefore labels deterministic conventions for those details rather than claiming production equivalence.

## Public API inventory and deferral

The 2026-08-02 `llms.txt` index exposes reference families for addresses, cart/purchase post, customers, entitlements, items, cancellation reasons, offer profiles, one-time incentives, orders, payments, product groups, products and rotations, free trials, generic resources, subscriptions and prepaid/bundle operations, plus one-click actions. It also indexes authentication, rate limits, cursor pagination, status codes, webhooks, and event payloads.

Only the matrix above is in the maintained contract. The immediate follow-up is the independently documented address/payment mutation set: create, update (activation/deactivation), and `use_for_all` for each resource. The legacy `POST https://api.ordergroove.com/customer/update_payment_default` operation has a different host, authentication, encryption, and request model and is outside this simulator's REST scope. Offers and incentives, entitlements, discounts, purchase post/cart, product mutation, rotating/digital products, prepaid subscriptions, bundles/components, webhooks, bulk operations, Storefront HMAC/trust enforcement, one-click actions, rate-limit simulation, and order-placement integrations remain deferred.

## Source hierarchy

1. Endpoint page and its embedded OpenAPI 3.1 fragment.
2. Authentication, cursor pagination, order status, resource overview, and data-model pages.
3. Relevant Ordergroove guides when an endpoint page refers to them.

The embedded fragments are source evidence, not copied wholesale: several are internally inconsistent or underspecified. Every normalization is recorded in `OPEN_QUESTIONS.md` and with `x-simulator-limitation` in the maintained specification.
